# DioxideLite 2.0.0 — black-screen fix / Setsuna visual parity

## Root cause found

The custom Skija screens implement `SkijaScreen`, and `TitleScreenMixin` switches the vanilla title screen to `MainMenuScreen`. However, the DioxideLite source was missing the Minecraft render-loop bridge (`MinecraftMixin`) that calls `SkijaRenderer.render(...)` after Minecraft presents its frame.

As a result, the custom screen existed as the active Minecraft `Screen`, but its `renderSkija()` method was never submitted to the framebuffer. The screenshot therefore stayed black.

## Fix

Added `com.dioxidelite.mixin.MinecraftMixin` and registered it in `dioxide-lite.mixins.json`.

The retained hooks are visual/runtime infrastructure only:

- render Skija screens after `RenderTarget.blitToScreen()`
- render the loading visual
- render in-world Skija HUD overlays
- dispatch pre/post client tick events used by visual modules
- update the window title to DioxideLite 2.0.0
- preserve the existing session accessor used by Alt Manager

No combat, movement automation, scaffold, kill aura, inventory automation, or other gameplay automation was restored.

## Setsuna visual comparison

The DioxideLite Pop/Drop ClickGUI and MainMenuScreen already contain the corresponding Setsuna visual architecture. The main missing piece was the render-loop bridge, so the UI code could not actually be displayed.

The DioxideLite Pop ClickGUI intentionally removes Setsuna's ESP/TargetHUD preview dependencies while retaining the general visual layout, animations, categories, module/setting presentation, and Skija rendering path.
